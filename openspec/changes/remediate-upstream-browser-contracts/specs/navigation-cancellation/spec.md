# Spec Delta

## Purpose

本能力规定等待轮询、原生导航推进与输入响应之间的取消边界。浏览器必须在有限期限内推进真实页面任务，在短轮询结束时保留已经消费的导航意图，在页面下载期间继续执行而非丢弃输入，并使根文档、子 frame 和新旧文档身份保持一致；修复不能关闭原生 watchdog、扩大无限等待或借提前成功回复掩盖动作没有执行。

## ADDED Requirements

### Requirement: RC-10 导航与等待取消边界

浏览器 SHALL 区分可取消的短等待与已经消费导航意图后必须有界终结的原生导航提交，使轮询切片结束不会丢失根或子 frame 导航，也不重复发送提交。MCP 的函数、选择器和文本等待 SHALL 在轮询间推进真实 fetch 回调、计时任务和导航，保留已修复的函数等待语义并补齐选择器与文本消费者。已支持的 CDP 键盘、鼠标和文本输入 SHALL 在文档发起导航的网络等待期间及时完成真实事件分发并回复，不得只确认接收却丢弃事件，也不得等整个下载结束才回复；未支持的触摸输入 SHALL 沿用 RC-20 的显式 unsupported 错误并在导航期间及时拒绝，不伪造事件或宣称新增触摸能力。既有导航期限、同步 JavaScript watchdog 和进程硬截止期限必须保持有效。

#### Scenario: 选择器和文本等待不会在切片边界丢导航

- **WHEN** 本地页面由真实计时任务发起耗时 150 毫秒的导航，而客户端分别调用 `browser_wait_for` 等待结果选择器和 `browser_wait_for_text` 等待结果文本，轮询切片短于导航耗时
- **THEN** 导航恰好发送并提交一次，两个独立场景都在声明的等待和导航期限内观察到新文档的真实选择器或文本；下一次 snapshot 与 evaluate 读取相同最终 URL 和内容，不会停在已消费但未完成的导航状态

#### Scenario: 函数等待的真实任务推进保持回归

- **WHEN** 客户端使用 `browser_wait_for_function` 等待真实延迟 fetch 回调、计时任务设置的值，或比单次轮询更慢的文档导航结果
- **THEN** 无需额外 evaluate 或人为唤醒就能观察到对应真实结果，既有函数等待修复保持可用；返回条件满足不是靠注入结果、伪造回调或只轮询静态状态

#### Scenario: 空闲等待遵守时间和工作上界

- **WHEN** 条件始终不满足、页面空闲，且请求的超时小于轮询间隔，分别调用函数、选择器和文本等待
- **THEN** 等待在所请求的期限及有限调度容差内报告超时，不额外睡完整个较长轮询间隔，不忙轮询占满执行线程；返回成功只可能来自真实条件满足

#### Scenario: 子 frame 导航不被误当作根文档替换

- **WHEN** 等待期间真实子 frame 通过表单或 location 发起导航，或随后根文档替换使旧子 frame 请求失效
- **THEN** 子 frame 独立完成时根 URL 与根文档身份保持不变，等待可观察该 frame 的真实结果；根文档替换后旧 frame 和旧文档结果不能回写新文档，交互引用只在其真实所属文档失效时清理

#### Scenario: Enter 提交期间 keyUp 真实执行且及时响应

- **WHEN** 客户端对本地表单发送 Enter keyDown，目标文档延迟 1.5 秒返回，并在下载期间发送匹配 keyUp，原文档记录真实键盘事件及其可观察副作用
- **THEN** keyUp 按仍有效的原文档事件分发语义执行，其响应在 500 毫秒内返回且早于慢响应完成，原文档的监听副作用可由受控端点观察，导航自行完成而无需后续 Runtime.evaluate；不得返回空成功但不分发事件

#### Scenario: 链接点击和其他页面输入不被下载吞掉

- **WHEN** 鼠标释放触发慢链接导航，客户端继续对该页面或同一连接的另一有效页面发送已支持的鼠标、键盘或文本输入，并另行请求未支持的触摸输入
- **THEN** 导航触发命令及仍可分发的已支持输入得到及时的真实执行和对应响应，其他页面的输入操作到其自身文档，不被误认为导航页输入而丢弃；未支持的触摸输入及时返回 RC-20 规定的 unsupported 错误且不生成 touch/pointer/click 事件，不把错误回复当作成功分发。所有原生执行仍遵守页面拥有线程和隔离环境进入边界

#### Scenario: 导航事件只描述真实提交

- **WHEN** 链接、表单或等待中的任务触发文档导航，并与停止加载、关闭、失败或较新的导航竞争
- **THEN** 成功时只发布一次对应新 loader 的真实文档提交和生命周期，失败或取消不伪造成功提交，文档发起导航的 referrer、空请求体 POST 及方法保持真实语义；同文档移动不误增一次新文档导航

#### Scenario: 有界提交不等于无限等待

- **WHEN** 已消费的导航超过单个轮询切片，或者网络永久不返回、页面执行同步死循环、客户端取消等待或调用停止加载与关闭
- **THEN** 单个轮询切片结束本身不丢弃已经消费的导航，导航仍受独立总期限、显式停止和关闭约束并产生可观察的完成或失败结果；同步死循环与失控进程仍由既有 watchdog 和硬截止终止，不把提交移出轮询当作延长无限执行的理由
