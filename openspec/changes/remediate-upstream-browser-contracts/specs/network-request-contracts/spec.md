# Spec Delta

## Purpose

本能力规定页面产生的网络请求在身份、请求模式、传输选择、拦截决策、地址授权、证书验证和渲染资源选择上的外部契约。修复必须让真实页面、嵌入式调用者和自动化客户端观察到同一请求的实际行为，同时保留文件、私网、代理、来源、证书及资源上限边界；不得通过关闭安全验证或省略本来需要的资源获得表面成功。

## ADDED Requirements

### Requirement: RC-01 请求身份与元数据

浏览器 SHALL 根据请求所属文档、实际请求模式、目标用途和完整重定向链生成 Fetch Metadata，而不是把脚本请求统一标成导航或把 `same-origin` 改成 `cors`。显式配置的浏览器 UA、platform 和 language SHALL 在实际 HTTP 身份、相关客户端提示及所属页面的 `navigator` 中保持一致，并遵守命令行与 CDP 的既有覆盖优先级；保持默认隐私 persona 一致不意味着必须改成宿主操作系统身份。

#### Scenario: 同源脚本请求携带真实模式和用途

- **WHEN** 本地可信来源页面分别通过默认 `fetch()`、显式 `mode: 'same-origin'` 的 `fetch()` 和 XMLHttpRequest 请求同源回显端点
- **THEN** 服务端分别观察到正确的 `Sec-Fetch-Site: same-origin`、对应的 `Sec-Fetch-Mode: cors` 或 `same-origin` 以及 `Sec-Fetch-Dest: empty`，而页面获得正常响应；没有用户激活的脚本请求不凭空携带导航用户激活标记

#### Scenario: 来源分类覆盖重定向链

- **WHEN** 页面请求同源、同站但不同源、跨站端点，以及先跨站再返回原站的重定向链
- **THEN** 各实际请求的站点分类遵守 schemeful 站点与公共后缀边界，完整链已经跨站时不得因最后一跳返回原站而重新宣称同源；模块依赖的身份仍属于发起文档，不以导入模块地址冒充新的文档来源

#### Scenario: 同源模式不因元数据修复而放宽

- **WHEN** 页面以 `same-origin` 模式请求异源端点，或同源请求被重定向到异源
- **THEN** 请求在不允许的跳转发送前失败，异源端点未收到请求；不得为了发送元数据把模式转为 CORS 或放宽来源检查

#### Scenario: 命令行身份在全部入口生效

- **WHEN** 操作者在子命令之前指定 `--user-agent`，分别使用 fetch、serve、scrape 和 mcp，并在支持的入口给出更具体的子命令覆盖值
- **THEN** 所有真实请求和页面 `navigator.userAgent` 使用最终选定的值，scrape 的工作进程不丢失该值，更具体的子命令配置优先于顶层值，未配置时才使用一致的默认 persona

#### Scenario: 两种 CDP 身份命令保持多文档一致

- **WHEN** 客户端分别使用 `Network.setUserAgentOverride` 和 `Emulation.setUserAgentOverride` 设置 UA、platform 与带权语言列表，再读取当前文档、已有及新建子文档、隔离世界和新页面，并发出普通或 stealth 请求
- **THEN** HTTP UA 与语言、适用的平台客户端提示以及 `navigator.userAgent`、`navigator.platform`、`navigator.language`、`navigator.languages` 反映同一已选身份；既有 UA 和语言能力不能因补齐 platform 而退化

#### Scenario: 身份覆盖不伪造已创建 Intl 的生命周期

- **WHEN** 已使用 Intl 的页面接受中途语言覆盖，或客户端显式重置身份覆盖
- **THEN** 浏览器保留已创建执行环境的真实 Intl 默认 locale 生命周期，正确更新受支持的 HTTP 与 navigator 身份并按既有语义重置；不得为伪装即时 Intl 切换而重建页面、丢失对象句柄或声称未实际发生的 locale 变更

### Requirement: RC-02 原生传输选择

浏览器 SHALL 在发送页面请求之前应用该页面已经选择的普通或原生 stealth 传输，覆盖经典脚本、原生表单提交及 CORS OPTIONS 预检，并保留已经正确使用页面传输的导航、模块和渲染资源行为。传输选择 SHALL 保留代理、信任配置、凭据、CORS、逐跳重定向授权与非幂等请求不重放语义，不得以另一个未配置客户端回退来掩盖失败。

#### Scenario: 原生传输覆盖三个遗漏消费者

- **WHEN** 启用 stealth 的页面经受信任的本地 HTTPS 站点加载经典与模块脚本、发起需预检的跨源请求并提交 POST 表单，分别通过直连和显式 CONNECT 代理执行
- **THEN** 脚本标记、预检后的业务响应和表单结果均可被真实页面读取，站点和代理记录证明这三类请求使用与页面导航一致的已配置原生传输、身份、信任和代理策略

#### Scenario: 普通模式保持原有传输

- **WHEN** 相同页面在未启用 stealth 或未编入 stealth 的运行方式下执行
- **THEN** 页面继续通过普通传输完成受支持请求，不依赖 stealth 才能工作，不因传输切换增加重复请求

#### Scenario: 预检失败不会发送业务请求

- **WHEN** 预检返回非成功状态、缺失允许的方法或请求头，或对携带凭据的请求给出不允许的来源与凭据组合
- **THEN** 页面得到 CORS 失败，目标没有收到被拒绝的业务请求；选择 stealth 不得绕过上述权限检查，也不得把自定义请求头通配符无条件解释为授权

#### Scenario: 重定向保留真实方法和凭据边界

- **WHEN** POST 表单或脚本请求收到 303、307 或 308，并且其中一跳改变来源或指向未获准的私网地址
- **THEN** 303 按浏览器规则转为相应 GET，307 和 308 保留方法与原始请求体，跨源凭据按既有规则剥离，未获准地址在发送前被拒绝；原 POST 不因客户端切换、传输错误或回退再发送一次

### Requirement: RC-03 请求前拦截与字节保真

浏览器 SHALL 对匹配 Fetch 拦截模式的实际请求在任何目标网络 I/O 之前等待客户端 Continue、Fail 或 Fulfill 决策，覆盖根与子文档导航、表单、经典及模块脚本、样式及其导入、渲染资源、fetch 和 XHR。Continue 的 URL、方法、请求头和原始字节请求体 SHALL 在发送前生效，Fulfill 的原始响应字节 SHALL 原样到达消费者；公共嵌入式接口、JS 与 CDP 不得依赖有损文本往返或相互矛盾的文本和二进制表示。

#### Scenario: 真正暂停而非完成后通知

- **WHEN** Puppeteer 或原始 CDP 客户端为本地页面启用匹配全部请求的 Fetch 拦截，并暂不回答某个导航、脚本、样式或样式导入的 `Fetch.requestPaused`
- **THEN** 对应端点在暂停期间收到零次目标请求，客户端选择 Continue 后才收到一次请求；脚本、模块、图像、CSS 资源与 `FontFace.load()` 原生请求均携带已认证发起文档的 frame 与 generation，字体加载同时保留父 frame，不能因构造器默认文档身份在目标 I/O 前被误判为旧请求；显式 FontFace 加载使用既有文档资源缓存阻止渲染器重复发现同一次加载，成功字节解除该状态，失败不自动重开同一请求，不建立全局 URL 黑名单；继续脚本且拒绝样式时，脚本的真实页面标记正常出现，样式未被请求或应用

#### Scenario: 四类 Continue 覆盖对所有请求路径生效

- **WHEN** 客户端对顶层导航和各类子资源分别覆盖 URL、方法、请求头及 base64 编码的二进制 postData
- **THEN** 本地回显服务仅收到改写后的目标、方法、请求头和精确解码的字节，原目标未被访问，页面使用实际返回内容而非原请求的完成后快照

#### Scenario: Fulfill 和原生二进制消费者一致

- **WHEN** 嵌入式调用者或 CDP 为暂停请求提供 `[0,255,128,195,40]` 的响应体，并且页面通过 fetch、XHR 或实际资源加载消费响应
- **THEN** 消费者读到完全相同的字节并正确使用相应响应状态与请求头，真实目标收到零次请求；原生 Fulfill 响应头与网络响应头使用同一小写名称映射和重复头合并规则，大小写不影响模块 MIME 判定或其他字段查找；同一规则适用于 Blob、ArrayBuffer、带偏移及长度的视图、FormData 中的二进制 File 和继承 Request 请求体的发送

#### Scenario: 无效 base64 不消耗暂停

- **WHEN** 客户端对有效暂停发送无效 base64 的 Continue 或 Fulfill，随后用相同 requestId 给出有效决策
- **THEN** 第一条命令明确失败且目标保持未发送，第二条命令仍能完成同一个请求，不产生请求丢失或字节替换

#### Scenario: 改写与放弃暂停不能扩大权限

- **WHEN** Continue 改写到未授权私网或文件地址、跨出 `same-origin` 边界，或者客户端断开或在有界处理期限内不回答
- **THEN** 地址、来源和文件权限仍在发送前执行；放弃的暂停有明确的有界终结结果，不因等待超时自动取得原本不存在的权限，不无限挂起页面

#### Scenario: 显式阻止与 Fetch 决策分离

- **WHEN** 某 URL 由 `Network.setBlockedURLs` 阻止，而另一 URL 仅匹配 Fetch 暂停模式
- **THEN** 前者按阻止语义终结，后者保留客户端可继续、拒绝或履行的真实决策机会；不得重新把 Fetch 模式当作静态阻止列表，也不得重复发布完成后的伪暂停

### Requirement: RC-04 文件与地址访问权限

浏览器 SHALL 在文件元数据查询或读取之前执行明确的文件授权，并对普通与 stealth 请求的 URL、实际 DNS 结果和每个重定向地址执行同一私网拒绝边界。操作者 SHALL 能通过可重复、可逗号分隔的 `--allow-network <CIDR>` 及环境等价配置仅豁免指定地址；该配置只放宽原有拒绝集合，不是限制全部公网流量的防火墙，既有显式全量私网授权语义保持不变。

#### Scenario: 文件拒绝先于存在性观察

- **WHEN** 未授权的嵌入式或远程 CDP 调用者分别请求实际存在、不存在和超出响应上限的本地文件
- **THEN** 三者均首先收到文件权限拒绝，不获得文件是否存在、长度或内容的区别信息；普通与 stealth 方式、复制后的浏览器上下文及直接底层加载入口具有相同结果

#### Scenario: 操作者文件授权不授予网页新权限

- **WHEN** 本地 CLI 操作者明确请求自己的文件，或服务以明确文件授权启动，同时网络页面尝试通过导航、重定向或拦截改写进入文件来源
- **THEN** 授权的本地操作按既有文件工作流可用，而网络页面仍不能越过原有跨 scheme 与调用入口权限边界；不借此次防御加固新增路径根目录限制或改变已支持的文件到文件工作流

#### Scenario: CIDR 仅豁免指定私网地址

- **WHEN** 操作者仅允许一个受控私网 CIDR，并同时请求该范围内的端点、范围外的 loopback、链路本地和云元数据地址以及本来允许的公网地址
- **THEN** 仅命中指定范围的原本拒绝地址获得豁免，其余原本拒绝地址仍被拦截，本来允许的公网地址不受影响；不指定豁免时保持原有默认安全行为

#### Scenario: DNS 与 IPv4 映射不能绕过范围

- **WHEN** 主机名实际解析到允许或禁止地址、localhost 延迟到解析阶段才可判断，或者相同 IPv4 地址通过 IPv4 映射 IPv6 表示，并包含允许端点跳转到禁止端点的链
- **THEN** 两种传输均依据实际将连接的地址和对应 CIDR 做一致决定，每一跳重新检查；未豁免的地址不会因主机名拼写、映射形式或前一跳已授权而被连接

#### Scenario: 配置错误与宽泛授权可见

- **WHEN** 操作者通过重复参数、逗号列表或 `OBSCURA_ALLOW_NETWORK` 给出有效前缀、无效前缀、`/0`，或使用既有全量私网开关
- **THEN** 有效列表按相同语义生效，无效前缀在启动时明确报错而非忽略，`/0` 给出可见的宽泛授权警告；既有全量开关仍是明确的全量豁免，不被暗中替换为更弱或更强策略

### Requirement: RC-05 证书链缺失恢复

浏览器 SHALL 仅在可归因于缺失中间证书的验证失败时，以有界 AIA 补链恢复普通与 stealth 连接，并将取得的证书仅作为不受信任的中间证书重新执行完整验证。补链 SHALL 保留既有信任根、主机名、有效期、签名、代理及私网权限，不得发送关闭验证的 HEAD 或任何其他应用请求来探测证书链，也不得因此重放已经发送的业务请求。

#### Scenario: 缺失中间证书的站点可被真实消费者使用

- **WHEN** 受控 HTTPS 站点仅发送叶证书，其 AIA 地址提供能连到已信任根的真实中间证书，页面分别通过普通与 stealth 直连及已配置代理访问
- **THEN** 完整验证成功后页面取得真实内容，后续相同链能使用有界缓存，服务端只收到已验证连接上的业务请求；需要观察证书链时也不出现验证关闭的应用流量

#### Scenario: 补链不创造新信任

- **WHEN** 相同站点改用过期、错误主机名、自签名、非受信任根，或 AIA 返回同名但非真实签发者的证书
- **THEN** 页面继续得到证书失败，服务端未收到未验证的业务请求；AIA 响应不能成为信任锚，也不能覆盖操作者配置的信任来源

#### Scenario: AIA 地址与递归处理有硬边界

- **WHEN** 证书指向私网、文件 scheme、重定向循环、超大响应、挂起响应、重复缺链或恶意证书集合的 AIA 端点
- **THEN** URL、DNS 和每跳重定向遵守页面既有授权，非 HTTP(S) 获取被拒绝，获取轮次、重定向、响应字节、总耗时与缓存容量均受有限上界约束；AIA 获取本身不递归触发另一轮无界补链

#### Scenario: 非幂等请求不被恢复流程重放

- **WHEN** 页面向缺链站点提交有唯一计数效果的 POST，或站点在已收到请求后断开连接
- **THEN** 只有证书重新完整验证成功才发送业务请求，已发送的 POST 不因补链或传输失败再次发送，操作者能够区分证书拒绝与实际业务结果

### Requirement: RC-24 级联选中资源的加载

浏览器 SHALL 仅为当前文档、媒体条件和有效级联实际选中的可用渲染资源发出预加载请求，包括所用背景、匹配且生成的伪元素背景、实际使用的外部 SVG 引用及所需字体。资源选择本身 SHALL 不产生网络副作用，并保留所用资源通过页面传输加载的真实画面、授权、拦截与字节上限语义；不得扫描全部 CSS URL 无条件请求，也不得关闭全部背景加载替代修复。

#### Scenario: 未使用的受保护背景不破坏登录状态

- **WHEN** 本地登录页每次访问都会更新 OAuth state，样式表中未匹配规则的背景 URL 会重定向回登录页，自动化客户端截图后完成授权回调
- **THEN** 服务端记录一次预期登录、零次未使用背景请求，回调使用原 state 成功，页面呈现真实登录结果，而非通过屏蔽所有渲染资源规避请求

#### Scenario: 级联实际使用的资源仍完整呈现

- **WHEN** 页面同时包含已使用背景、生成的伪元素背景、外部 SVG use、匹配所需字体，以及不匹配规则、被覆盖声明、未生效媒体规则和未使用字体
- **THEN** 服务端仅观察到当前画面所需资源请求，截图中对应背景、伪元素、SVG 和字体保持可见且正确；未选资源不因出现在样式文本里就被访问

#### Scenario: 动态级联改变真实加载集合

- **WHEN** 页面在首次截图后切换类名、媒体条件或有效样式，使原来未选的背景或字体成为当前使用资源
- **THEN** 后续截图按新级联加载新需要的资源，旧的未用 URL 仍不被额外访问；先前未选择不等于永久负缓存或彻底禁用该类资源

#### Scenario: 选中资源不能绕过页面安全边界

- **WHEN** 一个确实使用的资源指向未授权私网或文件地址，或者等待客户端 Fetch 决策，并分别运行普通与 stealth 页面
- **THEN** 资源仍遵守页面的地址、来源、代理、凭据、拦截和响应体限制，暂停前没有目标 I/O，拒绝不导致改用独立同步客户端偷偷请求
