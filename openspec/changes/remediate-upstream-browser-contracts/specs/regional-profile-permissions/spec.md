# Spec Delta

## Purpose

将显式启用的 GeoIP 解析、区域语言选择、原生日期与国际化表现、位置权限和真实 WebRTC 地址策略组成可验证的浏览器契约。区域身份只能源于实际有效出口或明确指定的 IP，位置配置不等于用户授权，地址展示也不能替代真实网络连通性；关闭功能时不得产生隐蔽的发现或下载流量。

## ADDED Requirements

### Requirement: RC-18 GeoIP 配置和权限一致性

浏览器 SHALL 将完整 GeoIP 模式、区域来源与覆盖、原生配置传播、位置权限及真实 RTC 地址/传输行为实现为一致、可观察且不绕过现有安全边界的契约；全部场景共同构成本 Requirement 的完成条件。

#### Scenario: 完整区域配置、权限与真实传输约束

**WHEN** 操作者通过受支持入口配置区域身份，页面及自动化客户端读取区域、请求位置或使用 RTC

**THEN** 下列模式、数据、传播、权限、地址和真实传输约束均生效：

浏览器 SHALL 为 CLI、MCP 和浏览器上下文配置提供关闭、自动发现有效出口和显式 IP 三种 GeoIP 模式。自动模式只能经该上下文实际使用的有效代理及其认证路径发现出口；未配置代理时才使用明确启用的直接出口发现。显式 IPv4/IPv6 模式校验并使用该 IP，不发起公网 IP 发现。代理主机的 DNS 地址不是出口证据，代理发现失败不得改用直接请求或主机身份。IPv4/IPv6 的发现来源和适用范围须区分，单一地址族不能证明另一地址族或旋转代理的未来出口。

浏览器 SHALL 在首次页面脚本和导航请求前，从本地地理数据库形成包含坐标、时区、国家及 locale 的一致区域配置，并依据有来源的 territory 语言人口权重选择语言。语言选择须在同一上下文内稳定，输入数据版本和选择种子相同时可复现，不能每次导航重新抽样，也不能以固定国家到单一语言的映射代替人口权重。国家作为区域配置元数据呈现，不新增虚构的标准 navigator 属性。

浏览器 SHALL 对每个字段保留可解释的来源，并让有效的显式 scoped override 优先于显式启动或配置值，显式值优先于 GeoIP 派生值，派生值优先于继承默认值。已明确设置的坐标、时区、locale、语言和地址策略不得被 GeoIP 覆盖。无独立覆盖时，`navigator.language`、`navigator.languages`、默认 `Accept-Language`、原生 `Intl` 默认 locale、原生 `Date` 和时区 SHALL 与所选区域一致，且传播至新的页面、导航后的文档、frame、window 及拥有这些接口的 worker realm；显式原始 HTTP 头覆盖只改变该头，不能被误称为已同步改变整个区域身份。

浏览器 SHALL 在原生国际化状态无法真正隔离时维持进程级区域配置亲和性：接受兼容配置，或在创建冲突上下文及执行冲突 scoped override 时明确报错；也可使用真实隔离承载不同配置。不得在已有 isolate 存活时通过修改共享原生默认值静默改变其他上下文，不得以仅改写 JavaScript 外观来假装原生格式化已经切换。

浏览器 SHALL 允许本地数据库及语言人口数据在无在线下载的条件下使用，并向操作者提供所选 IP 来源、数据供应方、版本或构建日期、适用许可及更新约束、所用记录的精度或未知精度状态。只有显式启用的下载或更新才可联网；关闭模式不进行 GeoIP 查询、出口发现或数据库下载。坐标和 `accuracy` 不得声称比数据库记录更精确，也不得附加伪造的高精度抖动。被明确请求的解析遇到无记录、缺字段、无效或不合许可使用条件的数据、网络失败或执行期限时，须在应用不完整区域身份前报告可观察错误，而非悄悄改用任意地点或语言。发现流量须服从既有地址、TLS、代理和执行期限保护，不带页面 cookies，不泄露代理凭据。

浏览器 SHALL 将位置数据与有效 geolocation 权限分离。对每个浏览器上下文和 origin，`navigator.permissions.query`、`getCurrentPosition`、`watchPosition` 以及 CDP `Browser.grantPermissions`/`Browser.resetPermissions` 须读取同一权限决定；配置坐标或开启 GeoIP 不会授予权限。未获授权的 headless `prompt` 和 `denied` 请求异步报告 `PERMISSION_DENIED`，不返回坐标；有效授权后才能异步返回位置。授权、重置、撤销、`clearWatch`、origin 切换及文档销毁须真实影响后续回调，并保留安全上下文、origin 及适用的 Permissions Policy 边界。

浏览器 SHALL 完成与区域配置关联的真实 WebRTC ICE 和 data-channel 地址行为：页面可生成有效 SDP、收集和检查真实候选、与独立对端建立连接并双向传输实际数据。候选事件、local/remote SDP、相关地址和 stats 中的地址信息须符合所选隐私策略，且可用候选必须对应实际可达传输端点。使用代理且要求出口一致时，STUN、TURN 及对端传输不得绕过允许的代理路径泄露直接公网或本地接口地址；可采用实际可用的受代理约束 TURN 中继，但不能仅重写候选地址、制造连接状态或用空 SDP/no-op 代替传输。显式 GeoIP IP 只选择区域身份，不会使网络自动拥有该地址；无法满足的强制地址或代理策略须明确失败而不泄露地址。某种代理不支持所需传输时的诚实失败不替代受支持代理场景中真实连通的验收，也不能将整个 RTC 部分排除为“不支持”后宣告本需求完成。本需求不要求扩展为全部媒体采集、音频或视频 API。

#### Scenario: 自动发现采用真实有效代理出口

**WHEN** 操作者通过 CLI 或两种 MCP transport 启用自动 GeoIP，并使用受控的认证代理和 IP 回显服务，回显服务按实际收到连接的源地址响应

**THEN** 区域配置使用该代理路径真实观测的出口 IP，首次导航和页面脚本已看到对应区域，回显服务没有收到绕开代理的直接请求，且操作者可区分发现地址族和来源。

#### Scenario: 代理失败不替换为机器或网关身份

**WHEN** 自动发现遇到代理认证失败、不可达代理、回显失败或执行期限，而代理主机本身仍能被 DNS 解析

**THEN** 创建或启动明确失败，直接出口回显端点收到零请求，不把代理网关 DNS 地址当成出口，也不运行带半套区域配置的页面。

#### Scenario: 显式 IP 和关闭模式均不隐蔽联网

**WHEN** 操作者先以合法显式 IPv4 或 IPv6 加本地数据库启动，再以关闭模式启动，并用受控网络记录全部发现及下载流量

**THEN** 显式模式仅按该 IP 解析本地记录，不发起出口探测；关闭模式既不查询 GeoIP 也不产生发现、下载或更新流量，现有显式手工区域配置仍有效；非法 IP 被明确拒绝。

#### Scenario: 坐标时区国家和精度来自同一记录

**WHEN** 操作者选择一个带国家、坐标、时区和精度半径的已知本地记录，在页面 origin 获得 geolocation 授权后读取位置及原生日期表现

**THEN** 区域元数据的国家和记录来源正确，返回坐标对应所选记录，位置精度以米表达且不小于记录的不确定范围，原生 `Date` 与 `Intl.DateTimeFormat` 的时区和日期换算一致，不出现虚构的十米定位精度或随机偏移。

#### Scenario: 人口加权语言稳定而非固定国家映射

**WHEN** 操作者使用含两个以上正权重语言的 territory 数据，在预先固定的种子集合上创建独立上下文，并在每个上下文重复导航、创建页面和读取语言

**THEN** 各种子结果遵守公开的权重选择规则与确定性期望，多个正权重语言均能被选中，不能总选同一国家的默认语言；相同种子和数据版本的结果可复现，同一上下文的后续页面不重新抽样，零权重或不属于所选 territory 的语言不会被选中。

#### Scenario: 真实请求和原生国际化共享区域身份

**WHEN** 本地页面发送导航、fetch、XHR 和模块请求，并在主文档、子 frame、新 window 和支持相应接口的 worker 中读取 navigator 语言、`Intl.NumberFormat` 与 `Intl.DateTimeFormat` 的默认解析选项及代表性格式化结果

**THEN** 本地服务器收到的默认 `Accept-Language` 与所选语言序列一致，各新执行环境的原生格式化及日期换算与该区域相符，普通传输和 stealth 传输都保持一致，不只在 JS getter 中显示正确字符串。

#### Scenario: 显式覆盖逐字段胜出

**WHEN** 启用 GeoIP 的上下文另外明确指定坐标、时区、locale 或语言，并对支持该作用域的页面施加显式 override

**THEN** 被覆盖字段取明确指定值，未覆盖字段仍采用已解析区域值，导航和新页面保持相应有效值与来源；单独设置原始 `Accept-Language` 只影响请求头，不被描述为同步改变 navigator 或原生 Intl。

#### Scenario: 冲突原生区域配置不污染已有 isolate

**WHEN** 一个存活上下文已使用某 native locale/时区，客户端请求同进程的另一冲突配置或对当前页面设置引起共享状态冲突的 scoped override

**THEN** 真正隔离的执行环境可分别得到所请求的原生格式化结果，否则冲突请求收到明确配置错误；已有上下文的 navigator、原生日期和 Intl 结果保持不变，错误回复不能是成功空对象。

#### Scenario: 数据缺失许可和更新边界可观察

**WHEN** 操作者使用无匹配记录、缺少所需字段、损坏、已不符合供应方更新条件或无法证明许可的数据，或在未授权下载的离线环境启用 GeoIP

**THEN** 操作者得到具体失败原因和数据来源状态，不发生静默下载或任意地点回落；合法本地数据库在离线环境可用，并可读取其供应方、版本、构建日期和许可信息，更新失败不会把损坏数据当成有效区域记录。

#### Scenario: 发现请求保持浏览器安全边界

**WHEN** 发现配置指向默认禁止的私有地址、无效 TLS 端点或经重定向离开允许路由的地址，同时浏览器上下文含页面 cookies 和带凭据的代理

**THEN** 未明确授权的目标被阻止，TLS 或路由错误可观察，发现请求和错误输出均不带页面 cookies 或代理秘密，失败不关闭安全保护；本地验收只通过显式私有网络授权访问受控服务。

#### Scenario: 配置位置不是授予权限

**WHEN** 本地安全来源页面设置了手工坐标或 GeoIP，权限状态仍为 `prompt` 或 `denied`，并同时调用两类位置请求

**THEN** `permissions.query` 保持实际权限状态，成功回调不执行，错误回调在后续任务报告 code 1；未提供错误回调不会转为同步异常或泄露坐标。

#### Scenario: CDP 授权和重置具备 origin 与上下文作用域

**WHEN** 自动化客户端仅向一个浏览器上下文中的 origin A 授予 geolocation 权限，并在 origin A、origin B 和另一上下文同时查询及请求位置，随后重置被授予上下文的权限

**THEN** 仅获准的 origin A 能返回配置位置，其他来源保持未授权；重置后已有 PermissionStatus 可观察到状态变化，后续 get/watch 不再成功，另一上下文的权限决定不被覆盖。

#### Scenario: watch 生命周期和安全文档边界生效

**WHEN** 获准页面开始位置 watch，随后位置被明确更新、watch 被清除、权限被撤销、frame 被移除或页面跨 origin 导航；另有 opaque origin、非安全来源或被 Permissions Policy 禁止的 frame 请求位置

**THEN** 有效 watch 异步获得允许的新位置，清除或销毁后不再回调旧文档，撤销后不再泄露位置；禁止来源不能借父页区域配置或权限获取位置，旧 origin 的授权不会跟随导航授予新 origin。

#### Scenario: 真实 STUN 与独立浏览器完成 data-channel 往返

**WHEN** 页面与独立 Chromium 对端通过受控本地信令交换真实 SDP 和 ICE 候选，使用本地 STUN 服务完成候选收集与检查，并建立 data channel 交换带随机 nonce 的文本及二进制消息

**THEN** 连接状态由真实网络进展到 connected，双向消息内容和 nonce 一致，STUN 服务观察到实际协议流量，候选、SDP 和 stats 的选中候选对、地址及字节计数反映真实连接，而非空结果或预设状态。

#### Scenario: TURN 和受支持代理下连通且不泄露直接地址

**WHEN** 页面启用要求代理一致的 RTC 地址策略，通过支持所需路由的受控代理访问本地 TURN 服务，在阻断直接对端路径的网络中与独立浏览器建立 data channel

**THEN** TURN 分配和中继产生真实流量，文本及二进制消息仍双向到达，SDP、候选事件、相关地址与 stats 只暴露策略允许的真实地址，网络观测确认 STUN/TURN 和对端流量未绕过代理，直接公网与不允许的本地接口地址均未泄露。

#### Scenario: 不可满足的 RTC 地址策略诚实失败

**WHEN** 所选代理不能承载所需 RTC 路由，或显式 GeoIP IP 与实际可用传输端点不同却被要求作为强制可达地址

**THEN** 连接或配置返回明确失败，不制造候选、不改写为不可达地址、不伪报 data-channel open，也不以直连回落绕过隐私策略；此前受支持代理及 STUN/TURN 的真实连通要求仍然必须完成。

#### Scenario: 地址族和出口变化不会被误报为一致

**WHEN** IPv4 发现成功但 IPv6 路由未被证实，或旋转代理在后续受控连接中改变出口

**THEN** 已知地址族、发现时刻和上下文适用范围可辨识，另一地址族不被伪称为同一出口；RTC 仍执行允许地址与代理策略，不能利用未确认地址族或变化出口泄露被禁止地址，也不能把一次发现宣称为所有未来连接的出口保证。
